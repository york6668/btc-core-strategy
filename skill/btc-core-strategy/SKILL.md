# 交易系统核心策略

受影响故障的修复诊断与业务执行分别处理，按[只读运维诊断](references/runtime-maintenance.md#受影响故障的只读运维诊断)使用原节点、故障证据及作者；固定读取的诊断结果不解除故障、不代签报告完成，也不放宽用量或平台拒绝。

当前新研究按 [交易决策主线](references/decision-design.md) 执行。公开阶段冻结未来1–3月的主路径、竞争路径与现价比较。个人在原配置决定中完成机会取舍与存量纪律。适用月度组合政策时，按当期有效配置先交付各组本月继续或跳过的决定及其理由，再交付计划金额、独立 BTC 价值区和熊市补偿。月度预算进入规划，实际执行由用户评估，未确认的持仓保持条件判断。正文消费综合判断、实际取舍与改变条件。旧不可变结果按原证明范围读取。


本 Skill 对应整个交易系统，BTC 只是其中一个标的。研究与报告范围沿下文用户已确认的资产及组合约定；历史仓库名、Skill 名和技术标识不缩减职责，也不新增标的或改变资产事实。

研究、规划与报告共同遵守[事实、判断与规划前提](references/core-strategy.md#事实、判断与规划前提)：用可核验的核心证据链支持当前结论，区分事实、受限判断与待验假设；未证实假设不能成为无条件规划前提。条件情景须有可观察支持和失效依据，报告压缩保留决定性口径、时间、反证与限制。程序保障引用和状态，模型裁决证据，不增加评分器或固定指标清单。

当前状态、有界未来竞争路径、公开现价价值和策略适用性分别完成，市场冻结后再作个人总体选择。完整研究比较同尺度更有支持的未来路径、真实竞争路径、机制及反证，允许低信心与具体未决；有限反馈复用有效结果并明确未完成范围，核心遗漏回原研究，不以未反转、条件清单或字段齐全宣称完整闭环。职责按[价值背离与时间优势](references/core-strategy.md#价值背离与时间优势)单一维护。

报告以框架识别的当前周期状态（中性／向上／向下）、价值与风险为主线，周期不是天数或周数。重点分别核验原方向推动力是否衰减、相反方向是否建立可持续趋势；上下两个方向均适用，动量枯竭和短暂反弹不直接等于反转。观察窗口、判断有效期和兑现窗口由问题、机制与证据另行维护，不能用延长预测期限代替周期答案。依据不足说明具体哪项判断未成立，不把未知写成中性。完整方法见[动量枯竭与反向趋势](references/core-strategy.md#动量枯竭与反向趋势)与[周期形态与下行方案](references/core-strategy.md#周期形态与下行方案)，专项验收按问题使用锁定真实数据复测或必要的实际运行证据，见原定时任务的[运行维护](references/runtime-maintenance.md#周期报告纠偏的持续验收)。

能力以完整分析、重要条件核验、必要研究、及时反馈、真实送达和持续维护验收，先满足这些需求，再优化成本和耗时。现有字段、结构、最小改动和复用偏好不能缩减需求；发现表达或执行缺口时修正对应接口及消费者。模型承担证据取舍与综合判断，报告明确呈现已形成的方向、适用周期、依据和个人应对，不能把冲突信号交回用户裁决。完整分析与报告完整的边界统一见[研判与报告的职责边界](references/mobile-report.md#研判与报告的职责边界)，研究、嗅探和报告阶段均适用；正文依据展开到足以解释主导判断，每段都应帮助理解方向、关键依据或行动；个人资产部分围绕周期主线和当前定价，交付参与、防守、等待的有据取舍、现货与空单含义、组合影响及必要限制；只有风险动作本身需要应对且有依据时才附加该动作，不能把全部建议限定为风险触发；总资金和占用比只是可选依据，不固化公式或自动调仓。完整核验和维护留在内部，成稿承接已形成的结果，不再注入完整研究指令或另作因子排序及解释。报告先完整交付独立市场主线，再交付个人总体取舍和改变条件；生成、冻结、到期续期、采用发送与完整事实核对留在技术依据。新稿按手机表达方法对照全文实质审查直接取舍、关键证据优先、内部维护分离及重复结论，不以来源绑定和条件齐全代替阅读质量。程序负责证据绑定、校验与恢复，不重排或追加正文；方法路径、字段齐全和测试通过都不证明分析已完成。

市场输入和仓位输入分阶段提供，先冻结独立市场结果，再进行个人适配；账户变化不使市场周期失效。完整投资决策、独立风险与机会、事前政策、分项未决复核及兼容要求见[完整闭环](references/closed-loop.md)；原市场字段及接续见[独立市场与分歧区](references/market-state.md)。模型内部完整维护周期关系、分歧区及双向风险，报告按其对综合判断和安排的实际影响表达。用户希望报告覆盖BTC及拟核对的币安QQQ、VOO产品，SPX/NDX保留为底层市场研究和历史引用；目标场所与简称不证明具体产品身份。[产品身份及报价](references/equity-products.md)须由对应公开原证核验，正文里的具体产品断言还须绑定该产品身份，不能用指数判断或点位冒充产品判断与价格。用户采用美元近似口径，USD与USDT常规微差不阻断分析或价位展示，保留股票USD/股、合约USDT的原始单位和产品身份；底层指数点位留在研究材料。三标的采集输入及适用性见[辅助采集消费](references/collector-evidence.md)。方向、周期、结构变化、共振或反转、依据和必要限制在研判中明确对象与确认程度，未知不写中性，市场依据不得含个人仓位或操作。组合建议按已确认配置确定适用对象、组数、成员和权重，并按配置生效时点承接变化；独立BTC／黄金是额外机会，保护另行评估。加密周期与错价修复、企业利润、货币与资产重估是收益解释机制，不是三个资产分类。本金保护优先；加密现货净多与保护配合，美股长期定投。投资原则和分析方法由[核心策略](references/core-strategy.md)维护，当前结论由 `.strategy/v4/current` 指向的 DecisionSnapshot 拥有。完整组合决策、事前记录、确认资料账本及按策略类型的验证反馈统一读[投资决策及反馈](references/investment-process.md)；必要责任不等于固定模块，工程和回放通过不证明真实投资效果。

研究作者独立分析、撰写完整中文报告并审阅确切映射候选；主执行者负责取证、嗅探、编排、核验、唯一正式写入和报告。正常工具沿当前宿主配置执行，真实平台限制仍适用。研究完成、正式采纳、观察完成和实际送达分别确认。

节点任务改造按[节点任务职责与切换验收](references/node-tasks.md)执行：数据节点持久记录待办、受阻、可执行、在途和完成，原研究/正式结论/投递各自仍为业务权威。小时只是旧自动任务与收盘数据的一种入口，不使任意时钟、触价或风险字段变化自动启动整套分析。新节点调度仅在无客户端模型、工具及原生投递实际验收且旧 ACTIVE 入口受支持停用后切换；此前保留原正式入口，隔离复测不推进正式状态。

## 固定本轮版本

先按[版本与节点入口](references/releases.md)固定本轮物理发布目录；脚本、Skill、方法与价值因子来自该版本。节点配置由 `BTC_NODE_CONFIG` 指定，数据保持原目录。新的活动运行沿兼容入口承接原研究请求、有效成果与未完成阶段，原作者和输入仍据原件验证；旧运行或历史恢复引用不成为新职责的前置。实际在途执行不换码，UNKNOWN 投递继续其原效果身份与固定版本；显式恢复既有版本引用时按该入口核对。

## 按当前阶段读取

个人阶段读取原 policy Owner 的无量投影。具备独立月度组合政策时，按[月度组合个人决策](references/investment-process.md#按月度组合作个人决策)比较，以最新适用的空单事实和独立的用户价格缓存形成条件判断。旧价格基线输入按[价格基线非执行合同](references/investment-process.md#按开仓价基线的非执行方向分析)消费。数量和由量派生的风险不作为方向判断前提；真实非量约束保留，执行安全门不放宽。

报告按[六项实质决策内容基线](references/mobile-report.md#决策内容基线及报告职责)核收：核心结论与定价、1–3个月前瞻、机会与风险收益、个人持仓与纪律、交叉验证及分歧、关键风险与失效条件。基线不固定章节或长度；投资决策完成实际相关方案和条件比较，报告只消费完成的决定，缺分析回原上游。云端原周度研究和事件按覆盖、时点及同源依赖对照，不新增报告追踪调度。

## 研究与恢复

职责沿原请求、有效成果和当前需求延续，不依赖旧代理或旧会话仍可唤醒。原 PUBLIC 作者与后继阶段执行者分别记录；先核原完成、在途、UNKNOWN 及具体拒绝，再由当前合格研究作者承接未完成阶段。新作者先读取 `research-read --phase public-result --request <原请求> --independent-id <原公开结果>` 的公开投影，核原条件与当前适用性，之后读取个人阶段或确切候选；承接不重跑已完成 PUBLIC，不改写原作者、证据截止或批准。实际作者、阶段领取、输入和完成证明仍沿原节点校验；新线程、摘要和测试通过均不能解除限制。具体原生证明及后继 followup 见 [研究阶段承接](references/v4-contract.md#研究阶段承接)。

启动及恢复先用 `recover` 的默认 PUBLIC 身份/计数视图，`report-care --run-ref <本轮引用>` 在市场冻结前也只返回公开时序标志。不要展开内部 `storage.recover`、旧 operation 正文或历史报告理由作公开输入。完整个人/报告恢复使用 `recover --run <本轮run.json> --run-ref <本轮引用>`；完整维护与报告上下文分别使用同样绑定的 `report-care` 和 `report-context`。程序核对本轮原run、root/project、公开上下文、冻结结果及真实阶段收据；市场候选、全局正式current或同名文件不能解锁。旧合法冻结沿原阶段产物核对，不重写原字节。节点 `core.recover` 默认只返回原operation身份/效果；完整回收显式提供已冻结的当前 `run`、`run_ref`，同时保留原operation_id、版本和UNKNOWN投递，不重放调用。

已知代码、契约、输入或语义缺陷先在原任务记录失败及受影响范围，停止该范围的模型执行；不靠研究作者重试找修复。按共享框架《模型缺陷与恢复》先用主执行者和隔离测试诊断、修复及验证；权限拒绝只待真实授权，容量/网络失败须有恢复证据。原冻结研究、已批准候选、Owner 与报告分别保留。交易系统不再设置项目级日历次数上限或“次日才可接续”；旧 `Asia/Tokyo` 日记录保留历史，不代表 OpenAI 套餐真实限额，也不表示平台无限额度。真实平台容量、用量、安全和权限限制仍须遵守。启动或续接前读取原 `issue_id`、阶段和节点 `model.deep.status`，在同一 `model.deep.BTC` 状态中按 issue/scope/phase/input 与稳定 claim_id 原子预留；只有 `CLAIMED_NEW` 允许实际启动。已完成同身份输入跨日复用原结果；原 claim_id 不换输入或阶段，在途和 UNKNOWN 未核清不得启动另一调用，响应丢失不得重复发起。失败须先修复受影响真实缺陷，不因日界自动解除；新后继阶段须有其实际输入和独立完成证明，不能把 PORTFOLIO 当 APPROVAL。取证、证伪纠错、个人适配、机械映射、报告和工程维护继续由主执行者完成；无实质新问题或未变输入不为取消上限重开研究，节点状态不可达时停止研究调用。

新小时公开市场材料在采集和模型候选前调用同一节点的 `model.defect.check(btc/market)`；开放的受影响缺陷阻断该新轮，已有固定运行允许用于原输入修复与隔离重放。该普通阶段准入与深评领取分别生效，不以深评门禁存在推定普通轮已保护；服务不可达时不默许新轮。
已核验的市场纠偏沿原节点缺陷台账保存原失败、影响、原因、修正及隔离复测引用；`model.defect.check` 的 `accepted_corrections` 随下一次正常 `run-prepare` 进入 observe read set。模型逐项回读原证据和修正版本，判断本轮实际结果是否采用且仍有效，失效或复发时按原 signature 重开缺陷并停止受影响的新轮。引用及测试通过不等于语义采用、真实报告送达或正式验收关闭；后续采用要用原业务产物和自然窗口另行证明。

原生 CLI 用 `model_guard.py launch-native` 通过节点预留后启动；原生协作代理工具无法由脚本技术拦截，执行者须在调用前用同一节点 `model.deep.claim`，真实返回后 `model.deep.finish`，把原 `claim_id` 传给 `research-independent`、`research-market-amendment` 或 `research-result` 的 `--guard-attempt`。丢失启动响应不得重试发起；缺原调用完成记录时拒绝新研究登记。机械映射、契约修复、测试、报告文字收尾交 主执行者；研究结果的来源、证据和独立实审要求保持有效，不能以预留或主执行者自签代替。

上述分工继续使用实际派发的研究作者，不把某种平台日志格式设为用户结果的永久前置。durable 执行按[v4来源适配](references/v4-contract.md#durable作者来源适配)核官方父子关系、实际完成与FINAL及不可变原稿；原接口未暴露的模型、effort、fork和入站正文明确保留未验证。claim仅证明准入及去重，不能填充实际型号或隔离证明；MAIN须审阅实际可得公开输入及阶段边界，不以作者存在代替内容审阅。个人阶段与完整候选批准由当前合格的实际作者继续，并保留各阶段来源，正式采纳和送达仍走原链，不重跑已完成PUBLIC来补形式字段。

durable MAIN 的来源同样按真实线程、回合及成功运行入口绑定，未暴露的 model/effort 保留 null；不得把原生调度预期自动写成运行事实。使用契约中的 MAIN 来源分支并在正式映射和报告消费时重验原件，不降低研究作者、候选批准和证据要求。

公开阶段完成后，候选审阅仍是独立待办；有真实完整候选且当前准入允许时，沿原研究及已完成成果继续后继阶段，不因日历次数等待次日，也不能将公开或 PORTFOLIO 完成证明代签 APPROVAL。主执行者 持续核验公开事实、个人适用性及旧已批准基线的报告；每个真实新模型阶段须核原调用、输入及新预留，已完成同身份结果复用。旧固定版本若不认识新票据视图，不直接登记新研究结果；核实原字节后按[版本与节点入口](references/releases.md)的原上下文兼容修复接续，不重置研究身份。

每轮沿[前瞻复核主线](references/core-strategy.md#前瞻复核主线)比较有效基线、新增及累积证据、因果与当前定价、下一验证；分别判断增量影响、原论点有效性和当前价格出发的风险收益。重要条件完整维护，方法按问题展开，不把固定模块、论点数量、窗口或报告篇幅当作必填清单。

接续旧公开前瞻时先核对原持久记录。旧 forward 可保留原窗口与条件，更新真实观察及复核，明确仅属事后判断；新命题或新 horizon 才按[可验证预期契约](references/v4-contract.md#内容-revision-9可验证预期与后继依赖)形成 lifecycle，不能为历史记录补造首次登记。公开引用逐项使用本轮 reference_index 的完整 `source_id/pointer/value_hash`，缺少散列或不匹配时修正本轮候选，不根据相似旧引用猜补。

前瞻包含[美债机会成本与风险补偿](references/core-strategy.md#美债机会成本与风险补偿)：模型按证据选择期限、基准和补偿要求，先形成情景再计算现价出发的回报，评估投资吸引力及新增风险。公共持有人成本可用于群体供需分析，不能代替当前价格、未来价值或用户个人成本；缺乏量化依据时保留具体限制。

- 首次缺少完整基线、实质反证、关键机制/风险范围变化、重大遗漏或原市场判断失去支持时，发起或恢复稳定的 `BTC_CYCLE`。普通新小时、时间到期与资料尚未公布只要求实际核验，不能冒充新研究理由。
- 用户明确要求完整重评时用 `USER_REQUESTED_REVIEW` 和真实 `user_request` 引用；同一请求复用原研究。此入口不增加 Scheduled 的自动触发条件。具体接口在运行入口与v4契约。
- 先读 `research.issues[].latest_request.progress` 及同级 completed_result、adopted_result、pending_candidates，核对原代理及实际请求，从已完成阶段接续。已采纳结果不会被较晚草稿覆盖；未处理草稿不自动重开完成研究，新请求独立判断。`NOT_CHECKED` 和归档记录不证明代理存活；旧请求结果不代表新请求完成。研究仍运行时，其他小时完成必要嗅探和报告判断后结束，不持续等待、催办或另派研究。
- 新研究只派生一个临时只读 研究作者，`fork_turns=none`。先给受控公开原始证据、明确标注日期的市场历史锚及中性问题，不传主执行者当前候选、嗅探判断或个人持仓偏好。先冻结独立市场结论与价格风险，再由当前阶段作者接收本地事实完成个人应对；不因持仓改写市场判断。新公开结果先按本轮正常入口返回的契约登记冻结，个人阶段汇合事前政策、风险与机会，完成候选比较及总体取舍而不改写市场正文；完整报告完成后，主执行者 映射并向本次实际审阅者披露确切候选。
- 同一研究的补证、映射及审阅继续原阶段；带有历史个人输入或候选的旧代理不能被重新标作全新独立研究。单轮输入读取校验只证明该轮读取，不证明整个会话没有先前输入；按实际研究请求和运行来源区分独立建立与续研。
- 当前合格研究作者核验具体候选和证据、反证、未决及复核条件；正文或市场含义需要改变时由它修正并重新审阅。主执行者 原文承接到 `conclusion.narrative`，最终 JSON 以 `report_narrative` 或既有候选正文的 `report_hash` 绑定同一实际正文；后者避免映射复核时重复输出全文，接口见 v4 契约。结构和身份校验不能替代内容审阅。
- 未决缺陷持续保留至正式修正采纳；未获批准不发布为新周期方案，已撤回价位不从历史回填。本轮市场核验、分歧区状态与突破迹象使用 MARKET_UPDATE，已核验的重要背离或波段风险仍可走 URGENT_RISK 反馈，不以中期反转、仓位变化或当日未报告为前提；新正式价位及个人配置仍须研究作者实际审阅、主执行者 采纳；仅个人事实变化可复用有效公开冻结及原请求，不重跑整个市场研究。仍有效部分继续保留；建议到期、适用性核验到期和研究触发分别处理。

BTC 回踩后的卖压与需求研判，以及持续下跌、筑底等相关问题，按[卖方衰竭场景方法](references/seller-exhaustion.md)选用日级指数和组成项。来源原值与复算口径分别解释，日值未覆盖本次回踩时仅作此前背景；新数值不机械触发深评。涉及原论点的历史修订须用当前及旧冻结引用比较组成项，解释判断影响；不能以旧批次或通用限制代替本轮研判。

## 运行与实际验收

节点启用 Docker 后，每轮同时按[持续分析契约](references/continuous-analysis.md)读取返回的 continuous-public；独立市场冻结后再读 continuous-personal。通过 BTC MCP 或 `btc-core data` 接续所有有效对象和未决条件，维护未出现在报告中的对象，提交实际复核并保留原期限、事实版本及未知。新增数据层不改变研究模型、市场优先顺序或真实发送协议。

生产使用 `$BTC_PYTHON` 和 `scripts/strategy_v4.py`。 精确承接使用固定版本 `run-value-ref` 返回的摘要，引用类型按本轮 vocabulary 填写；准备失败按运行入口显式复用冻结输入，不重新采集或自动重绑冲突。按运行入口执行 `run-prepare`，当前新入口先 market 再 observe；市场填写先用 `--stage market --check-only` 导出实际候选，再执行返回的 `review_read`（`run-read --run <run.json> --read-set <read_set.market_review> --cursor 0`），按 `next_cursor` 读取至 `complete`。每次工具输出预算采用返回的推荐值；若截断，在同一 cursor 减小 `--max-characters` 重读，不能仅打印摘要或解析文件后称读完。精确相同内容用指针去重，不借用原判断；完整理解后实际审阅，再以 `--input <market_candidate>` 冻结同一内容。输出 complete 仅表示材料输出完毕，不能写判断后同次调用直接冻结；分阶段 `run-advance --template <原模板> --answers <本轮判断JSON>`；旧 --input 完整稿兼容。只写判断及受影响内容，原始引用和已写源稿的精确承接由程序完成，接口见运行入口。`run-material` 默认只提供报告必要性材料；主评估用 `--stage main`，决定报告后用 `--stage report-body`。研究或绑定变化只刷新并复核受影响部分，失效模板不静默重绑；映射与正式写入使用同一校验的无写入预检。

周期证据主线按[事实、判断与规划前提](references/core-strategy.md#事实、判断与规划前提)维护：机制的应有响应、实际响应与留存、竞争解释及反证裁决接到现价价值和个人选择。方向、归因、延续和参与价值分别由自身证据支持；尺度由投资问题及完整结构决定，不按窗口长短定权。个人建议承接同一论证，账户缺口按依赖关系限制数量或动作，内部到期触发实质复核，保留旧期限与原研究身份。

验收沿真实材料进入研究、独立报告、映射批准、正式采纳、后续嗅探和实际报告逐段检查；指出具体输入输出如何支持判断，无法观察的环节保留未验证。程序测试仅证明接口与恢复行为。方法升级后的完整重评继续原研究与当前指针，不另建策略或常驻代理。

用量异常先消费节点已配置的共享 usage_guard：比较可观察的累计量与小时变化，实际异常或计量/完整性失效停止新的工作并持久锁定。参考不足可受监测运行，但不能称为正常或静默解除旧锁；历史观察上沿与正常样本分开，不机械等待7日，不将token代理写成真实积分或固定日额度。共享准入允许不等于恢复用户暂停的任务。具体能力及显式恢复见[运行维护](references/runtime-maintenance.md)。原额度缺陷另按 `run_usage.py --status` 与节点实际 usage_defect 检查；旧文件缺失不反复探测，也不阻止独立用量审计，原缺陷仍保留未验收。工程测试、自然运行、分析质量及真实送达分别验收。自动任务 memory 仅保留公开市场接续、研究/交付阶段与引用、待办状态和历史入口，不含账户事实、成本、目标比例、保护规模或个人建议正文；不逐小时追加流水账，不默认读取归档历史。父子无新材料不轮询等待，同一执行阶段只交一次有界工作包并消费实际完成结果。

当前完整报告的结论以未来1–3个月前瞻和个人执行纪律为核心，具体方法见[报告复核契约](references/report-care.md#前瞻结论与执行纪律)。市场仍先独立冻结，保留ETF吸收机制、主导与竞争路径及证伪条件。最后已知实际方向与其确认时点连续保留，后续变化未知不默认清仓；只对没有肯定持仓证据的资产使用未持有分析默认。当前价格基线模式使用已确认开仓价，数量及其派生集中度、绝对风险不作为方向处理门槛，不计算未知数量下的总盈亏或杠杆安全；其他有证据的非数量约束只限制真正依赖它的判断。

## 事实、权限与反馈边界

- 账户事实只来自项目内 `资产配置.md`、`操作记录.md`、`纠正记录.md`。首次研究或事实变化完整读取；同任务未变化可复用。未知实时字段保持未知，仍完成有边界的市场与组合评估。
- 目标、建议、价格触及和观察不能改变 `position_fact`。用户拥有真实资产事实、资金偏好及执行决定；本 Skill 不查询私有账户、不使用凭证、不执行交易或形成下单载荷。
- 小时嗅探验证完整报告的全部重要条件，包括手机未显示部分。按日本自然日每天至少实际送达一份有效报告，时机由模型判断；普通噪声和同义内容保持静默，重要变化及时反馈。证据缺失、运行失败和未知投递不能计作行情静默。
- 手机完成稿使用本轮返回的正文契约，先用 `run-advance --stage report --check-only` 导出并完整回读实际候选与来源，作全文语义审阅后绑定reviewed_candidate_hash；改写须重新核验，旧通过不迁移。遵守[研判与报告的职责边界](references/mobile-report.md#研判与报告的职责边界)，不设固定篇幅、栏目或因子清单。正文先给完整独立公开结论，再单向承接个人应用，最后概括保持各自范围；不把个人选择合成市场总裁决。必要限制直接说明实际影响，按内容使用清楚的阅读层次。冻结前逐段逐句删并重复、过程噪音和无关规则说明，详细理由集中表达，总裁决、主题选择与最后收束可作有功能的概括，核对关键依据、重要风险及未决动作影响仍准确；段落主题重要、预览清晰或自审通过不证明自然报告达标。内部维护字段不成为必备结尾，例行复核按时或提前完成及下一运行时点留在维护，失约和建议失效仍说明影响与补救。评级未变但风险含义有重要变化仍独立判断报告；云端VERBATIM原文展示，真实展示回读通过才算送达，实际正文质量另行核验。
- 重要事件涵盖市场变化、深评与重定价、重大风险、重要纠错及其他应报告含义。旧判断或价位失效、待复核先报告影响，完成后反馈结果。报告、深评和交付分别维护；未送达 REPORT 不被静默、证据受限或工具回执清除。旧 UNKNOWN 不锁新重要报告，按当前证据审查并至少一次送达，原请求独立回读；受控重试及义务覆盖见交付方法。
- 恢复按程序返回的 `delivery_recovery` 主动清单处理；`WAIT_FOR_NEW_EVIDENCE` 是已实际回读且内容已由验证送达稿承接的历史尝试，原 UNKNOWN 不变。无新证据不逐小时回读，不在最终回复、inbox 标题或摘要重复提醒；新异常、实质变化或需用户处理仍反馈。关联的新运输状态、实际回复证据或用户明确复查时沿原版本恢复，具体规则见交付方法。
- 沿用唯一交易系统主任务与既有报告目的地，不修改独立重大事件任务。Scheduled 及承接其职责的子任务不读写 Codex 长期记忆、不写资产事实或采集数据库；委派时传递当前适用的项目入口、阶段来源边界与执行限制，不假定隔离上下文继承父任务规则。宿主强制输出时如实保留 `SELECTIVE_NOTIFICATION_UNSUPPORTED`，通知保持仅失败。

新形成的可检验预期按判断生命周期及本轮登记接口固定形成、当时可知输入及原条件；公开反馈先核验实际机制与范围，再提出下一项待验预期。账户缺口影响存量净动作时保持该项未决，不将长期用途写成当前维持建议。报告按用户版面范例，以评估时间开头、完整加粗结论领起短段落，具体遵循手机表达契约；六点是实质内容基线，不是六个必填标题。市场结构、早期变化与机会取舍主导信息选择，个人段落消费已形成的净选择；内部字段、事实纠错过程和完整备选比较不进入正文。
