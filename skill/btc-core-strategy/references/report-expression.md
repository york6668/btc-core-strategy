# 简报表达（CONCISE_V1）

完整评估留在内部。常规用户正文只包含一行实际评估/行情截止时间、一句综合安排、一张上下沿建议表、最多两句必要说明。直接写决定、位置、金额；说明仅解释重要变化、依据及组合影响。重大风险允许增加必要短句，不展开完整分析、四条资金路径、五模块论证、复核义务或重复提示。不让用户自行判断市场条件。

## 草稿接口

revision 3主评估不含report。独立源稿的layout为`{format:"CONCISE_V1",overview,notes,risk_notes}`。overview是一句综合安排；notes最多两句；risk_notes仅用于主审阅确认必须额外说明的重大风险，通常为空。每句为`{template,bindings}`，不得嵌入额外表格或多段全文。综合句最多120字符，说明句最多180字符，每项一句；超限由本地改写，禁止工具截断正文。

- template可直接写经审阅的简短表达；数字用`{{/正式评估/字段路径}}`绑定，包括正文中的位置、金额、比例或周期，不能手填另一套数值。建议表由recommendations直接生成，每档一行，区分空单名义额与现货投入；无建议显示“当前不建议”，不填零或保留失效档位。
- bindings为`v4.semantics.stable(assessment)`中所述主题的当前hash映射：decision、outlook、robustness、portfolio、facts、recommendations、conclusion。主任务可用`v4.brief_report.sentence(template, assessment, topics)`机械装配。overview至少绑定decision和portfolio；一句可同时解释多个主题，绑定与控制字段均不进入正文。
- 主任务先比较正式语义，再检查每项重要变化是否被短句真实说明。工具拒绝过期绑定及未覆盖的变化；独立源稿及实际展示稿审阅必须核验“改了什么、为什么及影响”，不能只改hash/标签沿用失真的旧句。位置和金额不变时，预期、风险或保护目的改变仍须说明。建议撤回明确写撤回及必要原因，表格同步显示当前不建议。
- 不要求简报绑定内部完整narrative。outlook、robustness、五模块、建议理由/有效期/资金衔接等完整性仍由assessment与recommendations校验。未知字段保留在内部；影响建议理解或采用的重要限制（如空单保证金未定）用一句话交代。
- risk_notes每句绑定robustness，由主审阅核验其重大性和必要性，不作为普通长报告的扩写入口。不得通过简洁要求删除实质风险，也不机械重复所有未知字段。

## 兼容、静默与交付

完整结论可先发布，报告不参与主评估validate/commit成功条件。报告比较当前已完成策略与最后实际验收报告，深评完成和内部问题记录不自动报告。用report-source按同一版本layout生成冻结源稿，再由enqueue重验渲染、重要变化覆盖及源稿断言。源稿字段与收据详见[v4契约](v4-contract.md)。

云端仅一次排版、重排、去重和适度改写，不查行情或重新分析。回读实际助手展示稿，将每档位置与金额、口径、条件、期限、否定及不确定性与源稿逐项对应，保存真实消息关联并验收后推进报告基线。允许语义等价改写；不能仅证明数字集合相同，必须保留配对和条件含义。失真仅一次本地更正，失败保持交付异常，不重启深评。

新artifact为BTC_REPORT_V5。历史BTC_REPORT_V4及report.md仍按原冻结字节＋已收录回读恢复；不使用新renderer改写旧报告，不把旧ACK当新展示稿验收。格式迁移、同义改写或时间滚动本身不发送。尚未发送过时稿重判，发送中/未知先核实，不直接丢弃。
