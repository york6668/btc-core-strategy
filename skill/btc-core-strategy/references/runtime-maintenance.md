# 自动任务运行维护

完整分析、条件核验、必要研究、及时反馈和真实送达是降耗的前提。调用次数、报告篇数或测试通过不能代替这些结果。项目不设东京自然日深评次数上限；日历记录只承载历史，不能当作平台限额。调用通过既有节点按原问题、scope、阶段和输入去重并原子预留，已完成结果跨日复用；真正新阶段不因当天已有 COMPLETE 被迫等次日。实际平台限制继续遵守；在途/UNKNOWN 必须核清，响应丢失不得重启，开放缺陷须先按原范围修复。取消日上限不授权重复试错或以新阶段冒充批准。

## 日检查与三日自然验收

用量读取是对当前 Codex 内部结构的只读适配，不以某个 `state_N.sqlite` 名称作为长期接口。优先显式 `--db`，其次节点 `codex_state_db`；配置文件消失时，仅唯一且结构兼容的发现结果可使用，不按编号或修改时间猜选。返回 `source.status=UNAVAILABLE` 表示统计缺口，数值与达标情况保持未知，不更新为已统计，不阻断市场分析。已有原生接口能提供同等明细时可替代此适配，但账户额度百分比不能代替任务用量。

沿用原任务及原缺陷目录：`<本地既有缺陷目录>/`。缺陷为 `defect.json`，历史冻结比较基线为 `baseline-usage-including-descendants.json`。每轮运行先使用：

```sh
$BTC_PYTHON $BTC_RELEASE/skill/btc-core-strategy/scripts/run_usage.py --status --defect <本地既有缺陷目录>/defect.json
```

`--status` 只读且只返回上一完整日本自然日的待办与当前自然验收窗口，不展开历史。`usage_due=true` 时，按返回的 since/until/usage_output 调用同一脚本的 `--since`、`--until`、`--output`，加 `--baseline` 与 `--defect` 的上述路径。`quality_and_delivery_review_due=true` 时，核对代表性实际分析、必要研究与反馈、当日真实送达和未解决错误，在原 natural_acceptance.reviewed_days 简短追加该日证据及缺口。统计已完成但质量未核验时只补质量，不重复统计。

用量保留原任务、子代理及失败/未完成消耗；缓存已包含在输入中，不重复相加、不换算订阅额度。绝对目标为普通运行模型往返中位数不超过14；同类模型/effort/运行分组与冻结基线下降至少50%独立检查。跨模型缺少可比基线时相对项为未知，不冒充同类达标，也不能掩盖绝对目标失败。嵌套执行错误与非零退出按实际工具输出定位，同一次调用相同错误只计一次；未检测到错误不证明没有错误。

run_usage 同时按普通嗅探、深评及报告交付分组输出 elapsed_seconds 和 repeated_errors 的中位数、p95 与已知样本数。整轮耗时取主任务及子代理的实际起止跨度，不相加重叠代理时长；缺少时间或未完成保持未知。工程调试与普通自然运行分开，隔离材料缩减和程序测试不证明自然耗时目标已经达成。

本次切换的三个完整日本自然日在原 natural_acceptance.requirements_first_change 内记录，与旧失败窗口分开。逐日确认分析完整性、必要研究和报告、真实每日送达、重复错误与用量。三日完成后汇总同类比较；未发生的研究或恢复场景只声明隔离验证。缺少可比证据、存在未解决复发或质量/送达不足时保留未验收，不能关闭缺陷。脚本只补用量证据，未知或单日通过都不清除原失败，关闭仍需完整独立验收。

## 当前接续与恢复

Scheduled 不读取或回写 Codex 全局长期记忆。原自动任务的 memory.md 只保存当前必要接续入口、真实未完成效果及准确历史引用，不承载长期规范或由模型解释生成的新义务；需要更新时原地改写当前接续段，不逐小时追加流水账。旧全文归档在同一自动任务目录的 history 下，只有具体恢复问题需要时才读取。它不是资产事实、策略或送达状态的来源，不保存个人账户明细。

先依据正式研究进度和真实运行核对在办研究，再从已完成阶段接续；不能把 NOT_CHECKED 当作空闲，也不在原主运行仍取证、映射或发布时重复派生研究。同一错误没有新诊断不原样重试或重开研究。交付不确定按原发送尝试回读，不能用重新研究或重发解决绑定异常。

运行入口回退使用切换前保留的代码和提示词；已完成正式版本、观察、研究与真实交付继续有效，不能连同恢复副本回滚这些结果。工程问题保留本地，不进入云端投资报告。沿用原调度、模型、目的地和仅失败通知，不新增监控任务；宿主限制仍如实标为 SELECTIVE_NOTIFICATION_UNSUPPORTED。

## 按问题选择验收证据

每次验证的预期由当前有效要求及受影响行为确定。历史输入、锁定材料和旧案例只证明原版本、输入与条件下的观察，不因保留、摘要、重复使用或通过验证成为业务契约、长期保留义务或新执行门槛。材料随项目用途和恢复需要删除或归档；缺少旧案例不要求重建它来维持当前职责，确实依赖原效果身份的去重、拒绝和 UNKNOWN 仍单独核验。只有具体判断依赖原输入身份时才要求该原件；当前职责不以旧案例、旧输入可恢复或固定测试方法为前提。

分析、证据推断、策略表达与手机正文的修正，沿实际研究及报告消费链，根据本次有效要求选择当前取得或仍适用的真实输入复核。实际审阅上游证据、完整判断和最终正文，覆盖本次受影响场景；满足问题范围即可完成内容验收，不以另有自然报告为前置。原材料不能支持的具体判断仍保持未验证，补证按该判断的实际需要决定。合成测试、字段齐全或自评通过不代替这项实际复核。

锁定复测保留原输入身份、取得时间及当时可知边界，事后复核不冒充前瞻验证、盲测或全新独立研究，也不自动证明生产采纳或真实送达。调度、真实采集、实际采纳、发送与回读、自然耗时与成本，以及特定前瞻或后继条件，按问题所需的实际执行证据验收；已有证据可以复用，只有确需自然发生的部分才保留对应 natural_gap，并说明具体依赖。该缺口不扩成已通过内容的缺口。保留原缺陷身份、观察窗口和其他待办，不默改或延长窗口；关闭接口继续使用 preserve_window=true。

## 资产风险纠偏的持续验收

本项接入节点已核实的唯一当前主任务的正常运行和日检查，复用节点 acceptance-checks 中该项及现有 acceptance.defect 身份，归属 personal_allocation、report_delivery。任务 memory 只保留当前待办入口，不保存资产明细或逐轮流水。待办记录已发布版本、本机实际生效时间、新风险结果实际采纳时间、原报告本地引用，以及真实复测、运行证据和仍缺的具体依赖；仅部署成功不能填写采纳或送达完成。

正常轮次评估复用本轮证据，不额外发起验收研究。每日查看新版本实际输入、风险结论、必要报告和真实回读，分别核对：无风险需要应对时结论完整且不凑动作；风险需要应对时有清楚依据和简明建议，操作未决不编造；信息不足时说明具体判断边界，不默认安全、不制造比例或条件链。原有机会分析与市场冻结仍有效。原报告仅留在本机供回归，不复制到源码或长期记忆。

分析与表达按上述验收分流选择实际适用的真实输入复核，实际风险结论与完整报告消费审阅通过即可完成对应内容验收。确需实际运行的依赖按项保留缺口，回放不冒充真实采纳、送达或自然运行通过。发现复发接续同一项；调用 acceptance.repair 时将已验证部分写入 verified_scope、未覆盖场景写入 remaining_scope，指定 preserve_window=true，并回读 acceptance.status.partial_repairs；原缺陷编号和未覆盖场景持续开放，后续只能在原 remaining_scope 内逐项核实，不凭安装、合成测试或未经实际审阅的回放关闭。全部所需场景完成后将本地项标为完成，后续轮次不重复处理。没有新进展不重复通知，验收进度不例行附入投资报告。

## 周期报告纠偏的持续验收

沿用节点已核实的唯一当前原生任务、用户启用的频率、职责分工、报告目的地和通知设置。节点 acceptance-checks 中登记本项，关联现有验收类别 research_corrections、forward_outcomes、report_delivery；不重置全局窗口或其他待办。项内区分已发布版本、实际生效、修正结果采纳、更正报告送达、锁定复测覆盖、实际运行依赖及缺口，保存原报告和真实运行的本地引用。源码只保存有效需求所需的方法和正式实现；测试案例及构造程序按项目临时生命周期处理，不进入 Git 或源码导出。实际报告、账户、验收状态及运行证据留在节点；任务 memory 仅保留当前待办入口。

每轮先查看本项是否未完成，复用正常研究、观察、正式结果和必要报告的真实输出；有新的相关结果才补本地证据，每日复核一次新增证据，不重复扫描已审阅内容。核对实际输入如何支持主要投资周期、主情景和summary如何正式采纳、最终正文如何消费，以及真实助手回读是否相同。按问题判断内容，不以标题出现“周期”、字段齐全、正文哈希一致或自评通过代替质量审阅。当前用户纠偏可以立即作用于在办研究，但保留其原物理代码、研究请求、代理和已完成阶段；不为方法修订虚构程序兼容映射。

内容场景可用锁定真实材料分别复测：日内方向反复而周期依据未变时，主结论一致且没有无据动作；机制或累计反证改变时及时修正而不必等破位；周期证据不足时保留具体限制而不以小时判断替代；重大即时风险及时表达且不冒称周期反转；更正研究、正式结果和最终正文保持同一投资周期身份；实际采纳、送达与后继验证按本次问题所需另行核实。近端价格空间不得冒充周期价值或收益上限，同期限美债比较仍须有对应情景依据。个人风险与机会建议各自保持原边界。

分析与表达按上述验收分流选择实际适用的真实输入复核；完整源判断与最终正文已实际审阅时，不因缺少后续自然报告保留内容消费缺口。所选输入未覆盖的具体判断仍未验证，确需自然运行的项说明依赖并保留对应 natural_gap；事后复测不当作前瞻结果。仅测试、安装成功、运行次数或时间到期不能完成内容验收。不为验收增加研究、凑报告或重发 UNKNOWN；用户已经要求的更正研究及必要更正报告正常执行。发现复发接续同一项，保存受影响证据，修正对应环节后继续验证；已确认的其他场景和历史不清空。

本次所需内容场景与完整报告消费在适用的真实输入上复核并实际审阅通过后，可完成对应内容验收。实际运行依赖只影响对应项，不把等待自然输出设为内容修正的统一前置。绑定实际发布和审阅证据调用 acceptance.repair 时，只关闭证据已满足其实际范围的缺陷，指定 preserve_window=true；未验证的真实采纳、送达、前瞻结果及其他运行待办仍按原身份保留。已完成项后续轮次跳过专项，原定时业务、窗口及其他待办继续。没有新增进展保持安静；重要失败、需用户处理的缺口或完成只反馈一次，工程验收不例行附入投资报告，也不冒充整个节点或其他缺陷已验收。

## 今日用量异常保护

节点明确配置 `usage_guard_required=true` 和 `usage_guard.command/policy` 后，版本准入、研究预留、宿主业务入口及原生节点 worker 启动前调用共享 `codex-framework usage-check`。方法见共享框架 `york-workstation/references/usage-anomaly.md`；不另外建立计费器或调度器。锁后拒绝新的工作，已完成结果可只读回收。内部平台响应、在途调用、未接入入口及其他机器无法由本地程序硬拦截，不能声称覆盖真实账户每笔积分；原调度暂停状态不改变。

宿主 CLI 的具体覆盖是 `run-prepare/run-material/run-advance/context/observe/research-independent/research-orchestrated-independent/report-context/report-review/research-read`。其中独立报告入口不直接调用模型，但会生成大篇幅当前写作材料或重新构造并推进报告，必须同样准入。`run-read` 的有界冻结材料读取、`report-care` 状态诊断及既有结果导出仍可用于检查与恢复，不称为全部命令锁。容器内部沿宿主准入后执行；直接 Python 调用、绕过宿主的手工容器调用和任意文件阅读没有独立平台拦截，不能据此声称整个账户已停止消耗。

计量健康但正常参考不足时，共享入口可返回 `MONITORED_LIMITED_BASELINE`：正常性未确认，不因缺少7个正常日机械锁死。冻结且明确非正常的历史观察值可用于识别持续放大，不能自动转为正常基线；覆盖不到的模型/窗口保持未评估。实际异常、计量失效或完整性损坏仍锁定，跨重启及跨日保留；显式复核解除旧缺基线锁与恢复调度分别处理，已有暂停不会改变。具体变化判据与历史锁复核沿共享方法。统计保留 `usage_root_threads` 的历史范围及后代；独立 cron 节点另外显式配置 `codex_automations_db` 与 `automation_id`，从原生 `automation_runs` 合并该任务所有状态的登记根，不按名称或项目猜测。按原生 `root_turn_id` 聚合同一运行，失败和未完成消耗也计入成本，不按长寿命线程数或新增线程数冒充触发次数。缓存包含在输入内，不重复相加或换算积分。

共享 usage_guard 必须在原政策中保留旧 roots 并采用同一原生登记源的 `automation_selectors`，使用原 meter、锁和显式迁移复核。BTC 准入检查当前 `CODEX_THREAD_ID` 的原生元数据及父子归属，并核 guard 实际返回的 `source.root_thread_ids` 和 `source.automation_scopes`；缺身份、缺登记、读不到源或只覆盖旧根时，停止新业务和研究，不能以旧范围的零用量放行。尚无独立自然运行时，审计明确 `AWAITING_NATIVE_RUN`，只证明旧范围可读，不证明新运行已经验收。该适配器只读原生身份和用量，不读自动化提示词/报告正文，不修改 App 调度；`--root-thread` 仅用于明确的局部审计覆盖，不能作为准入绕过。

另建替代原生自动化时，以正式创建返回的新 ID 更新节点 `automation_id`，`automation_memory` 指向新任务自己的目录，不复制旧正文或依赖旧任务配置。原任务保持暂停；需要保留旧任务及迟到运行的专项用量时，把旧 ID 放入 `usage_history_automation_ids`，审计从同一已核实原生登记源读取并分别披露覆盖状态。历史 IDs 和静态旧 roots 仅用于计量，不授予新业务准入；当前调用的真实根必须登记到唯一当前 `automation_id`。共享 guard 同时计量这些新旧范围并保留原锁，源数据库名称不按旧配置或版本后缀推定。旧运行、报告、UNKNOWN 和 FINISHED 留在原业务记录中，不因替代调度重建或重放。此保护适用于已部署正常入口，不声称隔离任意修改的旧程序或直接服务调用。

专项 audit 与共享 meter 使用相同的原生会话表示：优先读取 metadata 对应明文 `.jsonl`，原生归档后读取同逻辑路径 `.jsonl.zst`，使用节点已有 `zstd` 流式解码，不落盘解压或改写源。只在压缩/物化切换导致路径瞬间失踪时有界重试同一逻辑文件；缺 decoder、坏档、缺文件及归档末尾不完整均保持计量不完整，不能当作零消耗或完整验收。

若原生父子边记录了后代，但相应线程元数据缺失，统计保留可观察成本并标为 `INCOMPLETE`，列出缺失身份，所有完成运行族暂不可认证；缺失后代不能记为零。共享准入此时拒绝计量，两者不将不完整范围视作正常基线。

`run_usage.py --status` 使用节点 `usage_defect`；没有有效旧缺陷时返回 `DEFECT_REFERENCE_UNAVAILABLE`，独立用量统计仍可使用 `--since/--until/--output`。失踪的旧文件不伪造补齐，原历史缺陷不因新统计成功自动验收。持续工作只读本轮简短状态与新增证据，具体诊断才读历史；父子采用有界工作包及完成通知，不空等轮询，不重复读已在本会话核验过的相同哈希材料。
# 受影响故障的只读运维诊断

`PORTFOLIO/NETWORK` 的原生进程创建失败使用同一 `model_diagnostic.py` 的 `READ_FAILED_PORTFOLIO_INPUT_SHA256_V1`。它只接受原 FAILED 票据绑定的 `BTC_BOUNDED_PERSONAL_EXPIRY_REASSESSMENT_INPUT_V1` 包，核原请求、公开 Owner 的原生作者以及本次官方失败 proof/唯一 FINAL；原生项必须是未截断的 `commandExecution failed/exitCode=-1` 和明确的 exec-server 创建失败。原生失败时段须落在原票据预留至失败结算期间，秒级原生时钟只容许1秒精度差，不能借同输入的旧失败证明另一调用。只有 FINAL 自称断连、普通业务非零退出、未知效果、其他作者或其他故障不能进入该动作。

固定读取范围为原运行生产的 run、MAIN context/template/read_set、冻结 market/result、差异及 observe 输入/回执，按角色限定位置、正常互相绑定及总计2 MiB；旧提案仅作内容寻址引用，不扩读任意候选或路径。配置权威根可规范化系统别名，但本轮生产者路径不能被软链改写，读取从该根用目录描述符逐级禁止跟随链接。原包、公开论证和失败来源不改写。执行仍先复核原用量、故障和15分钟期限，以 O_EXCL 执行意图先于完整材料读取；重复或并发执行不得多读。沿原父把 admit 返回的唯一固定命令交同一作者，verify 只核该命令和元数据。诊断不续用旧 CLAIMED 票据、不恢复业务、不清故障；实际恢复证据正常核收后，才经原故障入口和新受控调用身份接续未完成阶段。REPORT/APPROVAL 的原动作及全部旧限制保持。

失败的 `UNKNOWN/APPROVAL` 若原记录仅报告执行环境不可用、尚未读取候选或作内容结论，可用同一入口的 `--action READ_FAILED_APPROVAL_INPUT_SHA256_V1 --original-result-id <原已批准结果>` 核验原读取通道。`--context-path` 必须是原失败票据 `input_digest` 对应的完整 `BTC_FORMAL_FACT_REASSESSMENT_REVIEW_V1`；程序只读其固定清单，逐项核字节数、摘要及完整候选。原请求、已批准基稿、实际 FINAL 和原生证明共同导出同一作者，不能另填作者。该动作每个原失败票据只保留一次诊断，不因更换 run/result 参数重派；总输入上限2 MiB、原节点和ACTIVE运行、15分钟期限、真实用量准入及其他故障检查仍适用。成功仅证明原文件执行读取，不是候选批准、故障解除、平台解禁或消息通道容量证明。调用与核收使用原父的正式协作入口，不能因列表无活跃项就换作者。

旧 REPORT 分支由 `scripts/model_diagnostic.py` 在原工作站运行记录旁保留一次性诊断意图和证据，供已知失败的 NETWORK REPORT 核实原作者执行通道。它读取同一节点的 `model_daily.status` 与真实用量准入；不改变 `model.defect.check` 的业务阻断，不预留研究票据，也不清除故障。该 REPORT 分支仅支持固定动作 `READ_FROZEN_REPORT_CONTEXT_SHA256_V1`：完整读取与原失败票据摘要、原 ACTIVE 运行匹配的隔离 context，核对 JSON 与摘要，仅输出元数据。来源从节点已登记的原故障证据及 durable 失败原件导出原作者，不能另填作者、模型、命令或新分析输入。

先用 `admit` 在原运行的 `runs/diagnostics` 中 O_EXCL/fsync 保存固定动作、原故障、作者、输入、节点与代码绑定；该目录仅审计运维尝试，不是业务或故障权威。已有意图无论是否出现结果都不自动重派。每项故障只准一次同身份诊断，执行须在15分钟内开始，原在途/UNKNOWN、其他受影响故障、计量失效或拒绝继续阻断。原作者新回合只执行返回的精确 `argv`，通过 `read` 实际读取，不能附带报告、研究、交易、修复或任意命令。真实平台审批仍独立适用；该入口不提供模型启动器或扩大平台工具权限。

完成后 `verify` 消费正式读取的同作者新回合：唯一固定命令、完整输出、退出0及本地结果字节必须一致；普通文本自述、ROOT代读、另一作者或附带工具调用均不通过。诊断通过仅证明所测读取，不完成原 REPORT、不解除故障或许可正式采用。后续恢复仍由原故障机制按准确证据与平台限制处理；不得把诊断包装为已被拒绝的恢复效果。隔离及合成测试不证明原作者实际恢复。兜底维护须继续追踪实际诊断、恢复与原业务接续，不以接口新增或转交结案。

宿主自动产生的 `contextCompaction` 只有精确的 `type/id` 两字段时视为被动事件；不能携带工具、命令或其他载荷，未知活动和文件改动仍拒绝。旧 PORTFOLIO 诊断已执行并存在 `READ_MATCH`、但需由修正版核收此类原生事件时，只有 `verify` 可显式指定 `--original-release <原已安装提交>`。核收仍逐字节验证原 intent 绑定的旧脚本、固定依赖、节点、运行、argv、实际命令及结果；不加载或执行旧代码，不改 intent，另记真实新核收代码身份。该选项不进入 admit/read，也不重新执行已完成的读取，不能用它更换原执行身份或放行业务。
