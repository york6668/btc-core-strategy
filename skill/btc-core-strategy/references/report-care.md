# 报告修正依据与每日反馈

研判与正文分工遵守[研判与报告的职责边界](mobile-report.md#研判与报告的职责边界)。information 只记录实际展示的含义，引用最终正文中的原句；内部发现、维护分析和未展示条件留 maintenance。新数据、新冲突或未知解除先完成影响判断，不因尚未展示就自动生成报告；方向、风险或安排的实质变化、重要事实纠错与每日反馈仍须独立处理。去重以最后真实助手正文为依据，不能把内部分析或研究完成当作已送达。baseline_review 先指出当前重要含义在真实正文中的对应原句；没有对应内容就明确未展示，再判断当前重要程度。不得以同版报告ID、上一小时的分析或 maintenance 替代显示依据。风险比上一小时减弱也不证明用户已收到该风险。代码只拦截相同正文并核验来源，模型对照实际正文判断同义重复及重要新增含义。

维护对象是同一已采纳核心分析及报告的全部重要结论和条件，包括三类收益、本金保护及新配置建议。手机未展示的分析和条件从既有评估、研究结果及maintenance接续；读取这些材料、完整正文及business_meaning，再结合上一实际反馈逐项核验，不能只沿用短稿。美股定投、已有持仓减仓与回补使用其自身证据和交易日历；BTC两侧检查不是完整分析覆盖证明。

报告换版时，checked逐项复核上一版条件并说明继续、修正或退出的依据；triggers承接新核心报告的重要条件，refs指向同一assessment或本轮observation的真实结论；revision 5 删除旧条件时用retired显式记录id与退出原因。未决反证至修正正式采纳才解除；无变化保留原依据与分析时间，不能因新版本或新时钟丢弃旧承诺。report_basis绑定真实核心报告，分资产方向、条件和限制在摘要及云端回读中保持一致。

正式建议条件只能忠实展开正式报告的实际含义；MARKET_UPDATE 可维护本轮已核验的市场变化和分歧区迹象，不能冒充新正式价位。观察条件服务证据辨别，不能无依据地逐轮增加确认门槛、缩窄分析期限或强制回测。改变正式周期或建议价值时回同一研究审阅并采纳；本轮重要观察先按实际确认程度报告。未核验、来源失败与未公布保留UNKNOWN及影响，不以NOT_MET掩盖；未触发研究不证明VALID，须对照观察中的显式applicability_review。

市场识别、深评与报告分别判断。先对标普500、纳指100、BTC逐一核对评级、周期、当前结构、原结构→当前结构、依据与确认级别；小时承接、波段形态和中期趋势分别比较。历史结构锚或评级不变不能证明当前形态未变，资料不足明确未能判断的部分。已核验的重要结构变化、背离或波段风险可通过 MARKET_UPDATE 报告市场与分歧区更新，重大风险仍可走 URGENT_RISK，不要求中期反转、仓位建议变化或当天尚未报告；已展示风险的同义重复和普通反弹由模型判断是否新增实质意义。每日实际送达是最低要求；四小时只用于本次回放，不新增固定等待、跌幅或指标组合门槛。新正式价位与个人资产建议仍经深评采纳。

每份报告维护的是当前分析的适用性，不是数据表。主任务在内部说明判断为什么成立、哪些依据支持暂不更新、哪些变化会推翻或修正解释，以及最迟何时再核对。价格、周期和事件由模型据当期分析选择，不能统一套固定阈值、伪造新增变化或等待深评才修正。

报告采用[核心策略的价值背离与时间优势](core-strategy.md#价值背离与时间优势)结论时，maintenance沿用thesis/support/unresolved承载完整报告及本轮核验的依据与限制，明确哪些尚未展示，triggers承载关键收敛、成本或失效条件，recheck_at只表示最迟复核时间。checked.basis_review复核此前兑现预期是否成立；未按期出现时记录实际检查、解释影响和本次取舍，不能只后移期限。涉及正式周期、时间优势或市场建议改变时，先由 Astra 深评批准映射、Sol 发布，再独立判断报告价值；金额不变不构成跳过理由。旧报告未表达的分析保持历史未知。

下行风险复核还要检验原报告对两类已成交现货的减仓或不减仓依据、条件与保护覆盖；旧报告遗漏该问题时明确缺口并交回深评补齐，不由 Sol 补造旧结论。深评待完成时内部保留仍有效安排、受损条件和复核期限；手机保留仍有效的周期基准、建议价值和共识，明确实际受影响判断及其必要限制，不推迟必要反馈。

## 每轮顺序与每日边界

原任务每轮先调用`report-care --run-ref <真实本轮运行引用>`和recover，再取得可用证据。run-ref每次真实运行不同，同次执行保持一致，和report-review.provenance.run_ref一致。即使没有新完整小时，也检查当前报告触发条件及到期时间；report-care是只读入口，不依赖新市场包。event_check_required需要MAIN逐项实际审阅，不是让代码按价格机械决定策略。无变化可以复核后静默，但不能跳过检查。

每天至少实际送达一份有效报告，按日本自然日计算。模型选择report_by，说明事件/证据成熟/原调度依据，并在日界前为发送和回读留出足够时间；不写死推送时刻，不改原调度，不新增任务。report_by和recheck_at都必须考虑原任务下一次实际可运行的时点与执行余量，不能承诺任务没有机会执行的时间。未兑现的本日report_by不能反复后移。当天已有围绕深评的有效周期摘要、必要的有限反馈、重大风险提示或深评结果实际展示即可满足一次反馈，重要变化可追加；深评仅本地完成不计数。

到达所选时间且当天未完成反馈时，REPORT可沿用相同业务结论，通过独立daily_due理由，不必伪造重要变化。纯格式改写EXPRESSION_ONLY不计数。SOURCE与实际回复必须属于同一日本评估日，回读确认可以晚于当天，但以真实助手completed_at归属；跨日才显示的旧日稿不能填补旧日送达，也不能冒充新日判断。旧稿缺新字段保持未知，不补造历史每日验收，义务缺口从本政策启用日起派生。

断线/休眠后先核对待发送或未知消息，保留missed_days及实际送达时间。前一日未兑现且今日尚未反馈时进入补报义务；补当前分析，不伪造历史。发送后才延迟到复核期限以后的旧稿可以确认实际展示，但不计为当前有效每日反馈，恢复仍须到期复核。数据不足、运行失败或UNKNOWN投递不叫行情静默；EVIDENCE_LIMITED记录限制而不推进日反馈。若最近有效结构和现有证据足以形成保守完整判断，可REPORT并清楚说明实质限制，不把内部责任退回用户。

## report-review扩展

保持BTC_REPORT_REVIEW_V1兼容，在新review增加maintenance（旧冻结记录不改）。模型真实编写以下字段，示例不是市场判断：

```json
{
  "kind":"MARKET_REVIEW",
  "thesis":"当前报告的关键判断，不能只写维持不变。",
  "support":"哪些当期证据仍支持该分析，并怎样影响建议。",
  "unresolved":"尚未解决的问题及它为什么影响判断。",
  "triggers":[{"id":"稳定条件标识","condition":"会要求重新检查报告的具体价格/事件/周期组合，不当作自动成交。","reason":"解释该条件如何改变原分析，而不是只列一个价格。","refs":["/assessment/domain/value_zones/1/band/lower_u"]}],
  "recheck_at":"主任务选择的带时区最迟复核时间",
  "daily":{"day":"当前日本日期YYYY-MM-DD","report_by":"本日由主任务选择的带时区发送期限","reason":"为何选此时点，以及如何覆盖观察、发送和回读。"},
  "checked":{"prior_review_id":null,"basis_review":"对最后实际报告及上一检查逐项复核，说明继续静默或修正的依据。","trigger_results":[],"outcome":"VALID"}
}
```

kind支持MARKET_REVIEW、PORTFOLIO_REVIEW、DEEP_REVIEW、EXPRESSION_ONLY；没有真实深评不能标为DEEP_REVIEW，两类实质分析报告都可满足每日反馈。triggers至少一项，refs指向本轮冻结metrics或正式assessment的真实依据；事件可没有数值引用，但必须说明原因。复核条件中的价格与周期是MAIN报告判断，由证据推导；若改变持仓/资金等正式建议，先走主评估写入，不在报告中另建策略。

条件必须让后续任务能实际检查。“连续收盘”写清完整周期及先后次序；“卖压仍未衰减”写清比较窗口或可验证状态，并说明为什么值得修正分析。不能只把这些模糊说法放进结构化字段。价位注明真实产品和报价来源；USD与USDT按美元近似口径比较，常规微差不作为冲突或强制兑换取数理由。精确触价仍由对应产品、时刻和实际报价确认，股票与合约、VOO与SPY代理的身份不能混同。

checked.prior_review_id绑定report-care.prior_review_id，首次旧稿接续为null。trigger_results必须覆盖上一maintenance的每个trigger，旧结构{id,state,evidence}；revision 6 按[完整闭环](closed-loop.md)增加 scope/material，checked.outcomes 分别判断市场与组合，state为MET/NOT_MET/UNKNOWN，evidence写实际取得的证据及限制。outcome为VALID/REVISE/EVIDENCE_LIMITED。MET要求复核，不机械强制改变策略；REVISE必须REPORT，旧格式 VALID 且日反馈未到期才可 SILENT；UNKNOWN 不伪装成 NOT_MET。revision 6 独立保留市场和组合状态，已披露且无新增意义的个人缺口不污染市场有效性，重要未决风险仍须反馈。投递恢复独立于市场静默。下一recheck_at必须在未来；旧到期点不能被无审阅地覆盖。

已有缺口被核心报告披露，不等于相应维护条件已核验。实际现金、保证金或资金占用未知时，不能把“投入是否削弱缓冲”改成 NOT_MET；未取得新资料也不证明没有新发布。旧格式校验因 UNKNOWN 拒绝 SILENT 时，按事实使用 action=EVIDENCE_LIMITED、checked.outcome=EVIDENCE_LIMITED，不为通过校验改变触发状态。这只记录受限范围，不自动重做研究或重复发送已交付摘要，也不否定仍有证据支持的市场判断。同轮完整报告的 applicability_review、factor_checks 与 maintenance 必须如实承接同一受限范围；纠正误判时保留旧记录并追加修订，不能只修维护记录而留下“未取得资料却已确认无变化”的有效性断言。MET 表示该条件本身成立；“已经检查且事实未变”对于事实变化条件应为 NOT_MET，不能把完成检查写成触发。

本地事实文件指纹变化也可能来自已确认的概念文字修订，不能自动推断成交。完整研究待审阅期间可用EVIDENCE_LIMITED记录实际差异、影响与接续，无需为保存维护记录强迫生成报告；重要市场风险和每日反馈仍独立判断。该记录不确认事实适配完成，不改变正式建议，不推进送达，也不能把待核验差异写成SILENT。确需REPORT时继续明确事实适配限制和旧建议状态。

原report-review的reason、next_observation、baseline_review、applicability_review、information和MAIN provenance仍保留。context新增report_care，recover也给出每日完成状态、期限、缺口和复核需求。已到期/日界变化不能只因observation_id或decision_id没变化而跳过。

## 手机正文及交付

新稿使用 AUTHORED_REPORT_V1，按[手机表达](mobile-report.md)呈现已形成的综合方向、适用周期、依据与个人应对。内部覆盖的各期限、双方风险、冲突和未知不是正文必展示项；是否呈现取决于其对当前判断和行动的实际影响。没有有效新增建议时说明当前安排及原因，不追加撤回价占位行。分析缺项回原研究，表达缺项在冻结前忠实补齐，不借汇报另作判断。maintenance继续维护全部重要条件；旧格式、空块和冻结正文按原来源读取与恢复。

新带maintenance产物沿用既有report-review、独立outbox和真实回读接口。assistant.completed_at填写真实云端完成时间，落在发送开始与回读之间。AUTHORED_REPORT_V1在冻结前通过现有cycle_basis、deep_report_summary等审阅忠实性与必要信息，回读只核验真实关联和全文逐字一致，bindings=[]、checks={}；旧格式的语义检查仅用于原格式恢复。作者可使用冻结evaluated_at对应的评估时间首行，程序不自动插入，仅该已绑定且逐字一致的首行可从精确去重中排除。information只摘录实际显示含义。实际显示且验收通过后才能计入每日反馈；源稿冻结、运行完成或已收录都不等于送达。详细规则统一见[手机表达](mobile-report.md)。

尚未开始发送的跨日/过复核期限稿重新判断；主动恢复清单中的发送中/UNKNOWN先回读原消息。已分类为 WAIT_FOR_NEW_EVIDENCE 的历史尝试按交付方法等待新关联证据，无变化不逐小时回读或重复通知。确认后中断通过既有repair-completion恢复，日反馈由已验收不可变收据派生，不重复发送。后续自然主运行、触发复核及每日兜底分别验收，手动补发和隔离测试不冒充自然验收。

周期深评 recheck_at 是重新核验周期假设的必要期限；报告 maintenance.recheck_at 是内部必须履行的报告复核期限；下一小时嗅探时间是内部运行安排。三者分别维护，next_observation和维护字段必须填写不代表正文必须展示。按时或提前完成例行复核只记checked，正文交付实际判断；旧稿已对外承诺的期限继续履行，但不逐轮重述或自动新增对外时刻承诺。失约、建议失效及用户明确询问进度时，按[报告边界](mobile-report.md#研判与报告的职责边界)说明实际影响和补救；市场事件时间、判断期限与建议有效期继续按其实际含义表达。两类复核到期均先由 Sol 完成实际适用性核验，不自动要求完整深评；原期限和真实核验保留，不能无审阅顺延。Astra 原批准与完成时间不重写；建议实际有效期独立，到期只能保留待复核或经真实研究重新确定。待深评期间用已确认风险和限制完成反馈。

## 周期摘要的每日反馈

每日义务保留，普通小时独立核验当前变化和完整报告适用性，重要波段风险按相应期限报告，不因主要周期未反转而遗漏。报告到期可以复核并总结原周期判断，不能为凑每日反馈制造新结论。首次没有完整报告时在内部明确交付缺口及保守安排；已有报告但待修正时在内部保留仍有效部分、受损条件及期限。手机保留仍有效的周期基准、建议价值和共识，明确实际受影响判断及其必要限制。有限反馈可以满足当日必要反馈，但不能计为首次完整深评交付，也不能关闭待恢复研究。具体来源绑定见 v4-contract.md 的完整深评报告来源与摘要绑定。
