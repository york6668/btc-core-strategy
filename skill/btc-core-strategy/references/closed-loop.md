# 交易系统闭环

本文规定事实、判断、报告与复核如何承接。投资判断的比较方法见[交易决策设计](decision-design.md)，预期与证据的时点口径见[判断生命周期](decision-lifecycle.md)。程序接口由正式运行入口提供，部署配置负责原生运行绑定、用量范围和已授权目的地。格式与执行标识用于来源核对、去重和恢复。

## 启动与取证

项目主任务响应实际原生触发或用户请求。读取现行判断、已到期的条件、未完成的研究和交付义务，按本轮能够取得的证据和实际请求识别受影响的问题。每份证据保留原来源、产品和口径、观测时间及获知时间。辅助采集是待核线索，重复获取同一来源或经济事件沿其原身份判断。缺少可用运行机会时保留原期限及待办，在下一次实际机会核查影响。

研判先提供公开事实和明确标注原时点的市场历史。个人事实在公开结果冻结后按决策范围读取。原 BTCUSDT 空单的当前开单价从 Docker 持久记录读取。用户直接明确改价时，任务经宿主的专用入口保存并回读这一价格事实，独立于市场研判。仓位、配置、操作和纠正记录按各自确认来源及生效时点处理。

## 形成市场判断

市场阶段交付独立判断及其证据引用，说明中期主情景、最强竞争解释、关键传导与实际反应、当前价格下的风险收益，以及哪些后续事实能够支持或推翻判断。中期尺度由投资问题与证据确定，短期观察用于检验有关条件及识别即时风险。现货以低价积累为取舍依据，结合产品周期、合理估值、成本和下行风险判断是否达到参与价值。周期延续而价格或成本变化时，单独更新受影响的产品估值。市场方向、因果机制和现价参与价值各有证据，资料受限时明确受影响的结论。

只有真实的实质缺口、反证或用户明确请求才开展对应独立研究。以待解问题、适用范围和当时可知证据组织研究。接续原工作时沿原问题读取已有成果和在途状态。实质变更的候选按其确切内容与证据审阅后采纳。已经冻结的公开判断供个人决策引用，市场结论如需改变，回到市场职责重新裁决。

## 形成个人决定

个人阶段接收已冻结的市场判断、当期确认政策、最后已知实际状态及其缺口。按配置的成分、权重、用途和预算，在同一主情景及竞争情景下比较各组新增、等待留存、独立机会和存量。联合考虑未来净损益和组合容错，再形成各适用对象的具体选择。

- 月度定投逐组明确**本月继续**或**本月跳过**，说明决定性理由、主要风险、放弃的机会及改判条件。比较原计划、跳过和有依据的分批方案。金额来自所选方案，分批须说明为何优于原计划。证据缺口确能改变排序时，指出哪一组待定、缺什么和何时复核。
- 独立机会按自身净补偿及参与条件评估，存量仓位按持有目的比较继续、调整或退出。保护按被保护资产、实际覆盖和成本复核。暂停新增后的存量安排仍须依据本身的风险和用途判断。
- 原空单有确认的开单价时，按该基准比较减持、不变和增加并采用一个方向，经济依据与改判条件保存在原决定中。组合层汇总共同下行、敞口与保护覆盖，未知的仓位保持其事实状态，保护总额只计入已确认的覆盖。缺开单价时按可获证据判断适用范围，必要时保留条件动作。确实影响排序的缺口由研判核查。

组合评估及其成员决定通过正式任务的 `trading.portfolio_decision` 一并采用。记录确切市场和个人决定版本、共同情景下的净效果及实际依赖。成员决定保留适用政策、事实、期限及可核验的改判条件。从新证据判断哪些输入改变了备选排序，哪些只改变了核价时间或执行范围。对重要的跨轮安排，正式组合同时保存相对于原决定的取舍及理由。政策资料有缺口时，读回已确认的评估范围与其余对象的缺口。建议及计划按正式决定表达，账户记录的改变以用户确认的真实操作为据。

## 报告与交付

先核对原市场条件在本轮兑现了哪一部分，以及它对短期风险、中期情景、当前参与价值的影响。检查主路径和竞争路径对组合整体的净影响，再按所用估值、成员联动及个人事实复评受影响的决定。各组金额可以维持；若维持所依据的风险或成本改变，结合新的备选排序说明理由。用本轮已采纳决定与上次实际展示的正文判断反馈价值。所有报告均沿[整份报告](mobile-report.md)的模块顺序交付，完整依据承接有效的原文。首屏突出最重要的结果，盘中把稳定项目简述为可独立理解的现行结论。业务含义缺失返回原研判职责补齐，措辞问题在报告环节修正。正式研究尚未采纳时，可及时反馈已核实的重大风险，在完整结构内标清受影响且待复评的部分。

应反馈的内容成为待交付义务，正文与来源一起冻结。发送时核对该稿涉及的决定、目的地及实际效果状态。实质变更需要换稿时，明确新稿怎样承接尚未履行的义务。工具受理、已记录尝试和目标实际展示分别记录。与原尝试关联的真实完成正文核对通过后，才关闭对应交付义务并推进已展示基线。

投递效果未知时沿原身份核查回执和实际正文，明确拒绝时保留原范围及未履行义务。局部发送故障只影响相应交付，其他获准的研判、复评和独立反馈照常承接。具体原生接口及恢复见[交付方法](market-reporting.md)。

## 后续复评

在实际复评机会，用可归属的后续证据核对原条件、实际期限和作用范围，分别记录兑现、部分支持、反证、尚未到期和证据不足。新判断仍以本次真实形成时点和可获证据登记。对有兑现期限的预期，按原承诺的观察窗口评价事实，再按实际获知时点登记复核。改写、拆分、结束旧条件时保留原问题及已证范围，新的判断标准独立检验。证伪先修正或撤回受影响结论，再决定相关安排及反馈。旧报告、旧假设和重复观测各保留原身份与历史作用。

判断是否采纳、预期是否兑现、报告是否送达和用户是否实际执行各有对应的事实。正式服务持有当前判断、复评和交付状态，报告及查询引用同一结果。研究、格式、用量或交付的局部变更按自身影响承接。验收贯穿正常运行、逐组选择、实际正文和回执，并在取得相关新证据后核对原条件如何被复评和影响下一轮决定。
